## TERBUKA / meragukan

Tidak ada butir berstatus TERBUKA penuh. Butir yang bukan "Tertutup" bersih atau punya catatan:

1. **Peringkat stok-tersedia-dulu (§3.2) — Diterima sebagai gap (parsial).** Dasarnya hanya PLAN PR-03 ("opsional, bukan default"), bukan ADR. Parameter `preferStock` ada di API dan komponen `ProductSearchSelect`, tetapi tidak ada layar POS/form order/PO yang memakainya. Bila pemilik menganggap temuan ini harus dipenuhi di UI, status menjadi TERBUKA. Disarankan dicatat eksplisit di ADR-0018 atau PLAN §7 sebagai penyimpangan diterima.
2. **`ProductSearchSelect` tanpa pemakai (§3.2 hidrasi `productId`).** Backend dan komponen teruji, tetapi tidak ada halaman yang mengimpor komponen itu (grep seluruh `apps/web/src`: hanya berkas komponen dan test-nya). Hidrasi `productId` terbukti di backend, bukan di alur pengguna nyata. Dibiarkan Tertutup karena temuan menyebut kemampuan `search-options`, tetapi meragukan nilai fungsionalnya.
3. **Guard jenis member (KI-72) — Diterima sebagai gap.** Blokir tetap dibuang (D3 Default dipakai, belum dikonfirmasi pemilik); hanya peringatan jumlah terdampak.
4. **Kuota AI (§3.1) — Dibuang sengaja, rujukan tidak eksplisit.** Tidak ada ADR/PRD yang menyebut literal "kuota AI"; hanya tercakup lewat pembuangan Knowledge/RAG/AI (ADR-0018 D1, PRD §3/§9).
5. **Bukti pengiriman bertipe (§3.1 -> 3.5)** ditutup oleh DL-01 di luar cakupan bagian A; hanya ditinjau ringan (test `TestParityDeliveryEvidenceNeedsSignedDocument` ada).
6. **PR-08 (inline "Info tambahan:")** memilih error, bukan peringatan + migrasi otomatis; PLAN §7 menandai "tinjauan pemilik" — keputusan belum final tetapi temuan tertutup.
7. Catatan umum: test integrasi (DB) dan vitest tidak dijalankan di audit ini; status berdasar keberadaan dan isi test serta pembacaan kode. Di PLAN, `TestProductScanLookup` (PR-10) disebut sebagai nama test tetapi tidak ada fungsi bernama itu di kode (PR-10 bukan butir §3.2 analisis, hanya catatan akurasi bukti PLAN; lookup scan ada di `product/presentation/handler.go:349-355`, teruji di `products.service.test.ts:41` sisi klien).
