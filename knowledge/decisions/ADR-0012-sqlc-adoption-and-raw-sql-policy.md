# ADR-0012: sqlc for data access; hand-written SQL only by exception

## Status
Accepted (F8-18, 2026-10-09). Migration is incremental, module by module.

## Context
`sqlc` has been configured since the start but unused: every repository
hand-writes `QueryContext`/`rows.Scan`, so column lists, scan order and
nullability are checked only at runtime. The same optional-filter condition is
written twice (list and count) in several modules, and money/decimal parsing
helpers (`toFloat`, `parseDecimal`) are copied per module.

## Decision
1. Repositories use code generated by sqlc (one `sqlc` config entry per module,
   reading only that module's migration files). The module boundary is
   therefore enforced by the compiler: a query that names another module's
   table does not generate.
2. Optional filters use `sqlc.narg`, IN-lists use `sqlc.slice` (chunking stays
   in Go), money columns map to `int64`, decimals to `float64`.
3. The public `Repository` methods and the `contracts` types do not change; a
   per-module `mapper.go` converts generated rows to contracts types.
4. Transactions: the repository exposes `InTx(ctx, fn)`; rows are always fully
   read and closed before another query runs on the same transaction
   (`.claude/rules/database.md`).
5. Time: queries receive `now` as a parameter (`timeutil.NowUTC()`); `UTC_TIMESTAMP`
   and `CURDATE` are not used in sqlc queries.

### Hand-written SQL
Allowed only when ALL hold: sqlc cannot express it (dynamic column/table sets,
dynamic ORDER BY, variable-arity multi-row INSERT, a MySQL feature the analyzer
rejects); no `narg/slice/embed` equivalent exists; the statement carries a
`// raw-sql: <reason>` comment and an entry in `scripts/raw-sql-allow.json`
(file, reason, ADR, review date); and an integration test covers it. No runtime
query builder is introduced.

## Consequences
`scripts/arch-check.mjs` (rule C) checks real generated files, and counts raw
`QueryContext/ExecContext/QueryRowContext` outside the allow-list as errors once
a module is migrated. The migration order is smallest-first (media → finance);
each module is one reviewable, revertible change guarded by characterization
tests against `mini_erp_test`.
